  3. 대상 선정: python3 safety_jobs/cover_letters.py --briefing $W/br_<1>.json --briefing $W/br_<2>.json --done $W/drafts/index.json --exclude $W/drafts/excluded.json --exclude $W/drafts/excluded_jobs.json --requested $W/drafts/requested.json (브리핑을 URL 기준으로 합치고, 마감 10일 이내와 '채용 시 마감' 공고를 고용형태·기업 구분 없이 고른다, 제외 목록·장애인·보훈 전형은 빠짐, target.file 이 저장 경로 — 마감일 없는 공고는 drafts/open_.md). 오늘 마감(days_left 0)은 건너뛰고 보고에만 적는다. 지원 자격상 지원자가 지원할 수 없는 전형(간호사·보건관리자 면허 필수 등)과 이미 초안이 있는 같은 채용의 다른 사이트 공고(예: 한미그룹 공채 잡코리아 공고 = 기존 한미사이언스 초안)는 새로 쓰지 않고 보고에 적는다. 대상이 많으면 Agent 도구로 서브에이전트에 4~5건씩 나눠 병렬로 쓰게 하고(각 에이전트에 이 지시의 [작업 폴더]·[절대 규칙]·[작성 우선 규칙]과 4~4-B 단계를 그대로 전달하고, 아티팩트 게시는 하지 말고 $W/out 에만 쓰게 함), 마감이 가까운 순으로 하루 최대 30건, 나머지는 다음 날로 넘기고 보고에 적는다. generated_at 이 오늘(KST)이 아니면 보고에 알린다. 4-A. 사용자 수정 사례: python3 safety_jobs/cover_edits.py --answers $W/db/answers --drafts $W/drafts --out $W/drafts/edits.md 를 실행하고 edits.md 를 끝까지 읽는다. 이후 모든 초안에 [작성 우선 규칙]의 '사용자 수정 반영'을 적용한다. edits.md 는 게시하지 않는다.
  4. 초안 작성(공고마다): archive/00_README.md 의 '새 자소서를 쓸 때 순서'와 archive/01_guide.md 의 2~4절을 따르되, 위 [작성 우선 규칙]이 우선한다. - 문항·글자수: WebSearch 로 이번(없으면 최근) 문항을 찾는다. 못 찾으면 공고 detail_text 의 문항, 그것도 없으면 과거 문항을 쓰고 머리말 questions 에 '추정 문항'과 근거. 글자수를 모르면 800자로 보수 가정. - 자소서 양식이 없을 때(이력서만 받거나 문항이 전혀 없음, 인재 Pool 등록 포함, 규칙 30): 회사(또는 그룹) 채용 홈페이지의 신입 자기소개서 형식·인재상·합격 사례를 찾아 그 문항과 글자수로 구성하고, questions 에 '홈페이지 채용 정보 기준 구성 — 근거'를 적는다. - 기업 개요(규칙 31, 필수)와 기업 분석(공고 요약 / DART / DART 안전·신사업 적합도 / 안전보건 기준 / 최근 1년 안전 기사 또는 주요 기사 / 최근 1년 AI 기사 / 사고 데이터 활용 / 연결 포인트 / 신입 연봉(채용 브리핑 extra.starter 값을 굵게, 없으면 '신입 초봉 확인 못 함(채용현황 브리핑)') / 회사 복지(규칙 37)). - 외국계 초안이면 한국어 문항 뒤에 규칙 40의 영문 커버레터 문항을 붙인다. - 다듬기: humanize-korean·korean-proofreader 스킬이 있으면 적용(인용 원문과 확정 문안은 제외). - 글자수: 문항마다 줄바꿈 제외·공백 포함 기준 한도의 95% 이상, 한도 이하(규칙 48, cover_check 가 오류로 잡음). 넘치면 확정 문안이 아닌 문장을 줄이고, 모자라면 원본 자료·확정 문안·기업 분석에 있는 사실로 채운다. - 형식: safety_jobs/cover_brief.py 맨 위 docstring 의 md 형식을 정확히 지킨다. 파일은 target 의 file 경로로 $W 아래에 저장하고, $W/drafts/index.json 에 {url, file, company, title, deadline, written} 을 추가한다(마감일 없는 공고의 deadline 은 '채용 시 마감'). 4-B. 문맥 재검토(필수, 초안마다): (a) python3 safety_jobs/cover_check.py $W/drafts/<새 초안>.md --guide $W/archive/01_guide.md --briefing briefings/latest.json 을 실행해 [오류]가 0이 될 때까지 고치고 [경고]도 가능하면 없앤다. (b) 모든 문항을 처음부터 끝까지 다시 읽고 STAR·CPSBS 순서, 태권도('고3 때 딴'), 중앙점 없음, 회사 이름·사업·수상·기준이 그 회사의 것인지, 반복이 없는지, 원본에 없는 사실을 덧붙이지 않았는지, 문항에 답했는지, 영문 커버레터가 같은 사실만 쓰는지 확인한다. 고쳤으면 (a)를 다시 돌린다. 4-C. 저장 답변 수정 문구를 기존 초안 전체에 반영(규칙 39·45, 매일): edits.md 에서 새로 생긴 수정 사례(전날까지 이미 반영한 것은 제외)의 고친 문구를, 제외 목록에 없는 기존 drafts/*.md 의 같은 뜻 문장에 자연스럽게 반영한다. 저장 답변이 있는 문항(answers db 에 초안id_문항순번이 있는 문항)은 md 를 고치지 않는다. 회사 고유 내용은 옮기지 않고, [절대 규칙]과 부딪치는 수정은 따르지 않으며, 같은 경험이 한 초안에 두 번 나오게 되면 넣지 않고, 글자수 한도를 넘으면 확정 문안이 아닌 문장을 줄인다. 확정 문안을 고친 사례면 archive/01_guide.md 의 '### 확정 문안' 블록도 고친다. 확정 문안이 옛 문안으로 남은 기존 초안(저장 답변이 없는 문항)은 최신 블록으로 고치고, 중앙점이 남은 답변은 쉼표로 바꾼다. 영문 문항이 없는 외국계 초안에는 영문 커버레터를 추가한다. 고친 초안마다 cover_check 를 다시 돌린다. db(answers)는 쓰지 않는다 — 저장 답변 안에 옛 확정 문안이 남아 있으면 보고에 '저장 답변 갱신 필요'로 적는다.
  5. 브리핑·HTML 생성과 게시: python3 safety_jobs/cover_brief.py --drafts $W/drafts --out $W/index.html --exclude $W/drafts/excluded.json --answers $W/db/answers --briefing $W/br_<1>.json --briefing $W/br_<2>.json --history $W/history.txt --expired-out $W/expired.txt — index.html, 같은 내용의 날짜 사본 briefing_YYYY.MM.DD.html(머리말 '지난 브리핑' 줄에 최근 7일 사본 링크), 화면에 보이는 초안의 오늘 날짜 letters/_YYYY.MM.DD.html 이 만들어지고, 보관 기간이 지난 파일 경로가 $W/expired.txt 에 적힌다. 그 뒤 Artifact 도구로 url=https://claude.ai/artifact/GEkympcXxpmb48ez87mY99, file_path=$W/index.html, root=$W 로 publish 한다. files 는 경로를 키로 하는 객체 형식으로, drafts/index.json, 오늘 새로 쓰거나 4-C에서 고친 drafts/.md, 고쳤으면 archive/01_guide.md, $W/letters/ 에 오늘 만든 letters/_YYYY.MM.DD.html 전부, 오늘 briefing_YYYY.MM.DD.html 을 자기 경로로 넣고, $W/expired.txt 의 경로(history.txt 에 있는 것만)를 null 로 넣는다. 한 번의 publish 는 250개 항목 이하로 — 넘으면 null 항목을 나눠 같은 file_path 로 두세 번 publish 한다. 아티팩트 전체 파일이 512개를 넘으면 게시가 거절되니, 거절되면 그 메시지를 보고에 적는다(icon·capabilities 생략 — 생략해야 db 권한이 유지됨; excluded·requested·edits.md·history.txt·expired.txt·db/ 는 보내지 않음). 게시가 '더 새 버전' 때문에 거절되면 그 버전을 읽어 합친 뒤 다시 게시한다. 대상이 없어도 다시 만들어 게시한다. 게시가 끝나면 Artifact action "open" 으로 url=https://claude.ai/artifact/GEkympcXxpmb48ez87mY99 를 띄운다(항상, 2026-10-20 사용자 요청). 5-B. 에이전트 작업현황(항상, 저장소 CLAUDE.md 규칙): 시작할 때와 끝날 때 https://claude.ai/artifact/7q7cTurJbjF1jEczWCR1Lx 를 Artifact read 로 받아 맨 아래 JOB 데이터만 고쳐 같은 url 로 다시 publish 한다(icon 생략, 파일은 $W 아래에 둠). 메인 카드는 '자기소개서 일일 브리핑 루틴 (YYYY-MM-DD 20:30)', 하청 카드는 단계별(대상 선정 · 공고별 초안 작성(서브에이전트마다) · 문맥 재검토 · 기존 초안 수정 반영 · 브리핑 게시)로 두고 status·progress·결과 한 줄(건수·업체명만, 자소서 본문·개인 정보는 쓰지 않음)을 적는다. 이전 작업 카드는 지우고 오늘 실행 카드로 바꾼다.
  6. 최종 답변(푸시 알림·이메일로 전달): 맨 위에 아티팩트 링크를 굵게(오늘 사본 briefing_YYYY.MM.DD.html 과 보관 기간이 지나 지운 파일 수도 함께 적는다). 오늘 새 초안 건수와 공고별 업체명·공고명·고용형태·마감(D-n 또는 채용 시 마감)·공고 링크·문항 출처(확정/추정/홈페이지 기준 구성)·지원 전 확인 필요 사항·외국계면 영문 커버레터 단어 수·문맥 재검토 결과(cover_check 오류/경고 수와 직접 고친 점)를 표로. 사용자 수정 사례 반영 결과(edits.md 의 바뀐 문항 수, 새로 따른 수정 경향 한두 가지, 4-C에서 기존 초안에 반영한 곳 수와 업체명, 절대 규칙과 부딪쳐 따르지 않은 점, 저장 답변 갱신 필요), 넘긴 공고와 건너뛴 공고(오늘 마감·중복 채용·자격 불가 전형·하루 한도 초과), 찾지 못한 조사 항목을 짧게. 이어서 작업현황 링크와 상태 표(에이전트 · 맡긴 일 · 상태·진행률)를 넣는다. 마지막 줄: "지원 전 공고 원문 문항·글자수와 대조해 고칠 것".
