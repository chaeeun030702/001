Chrome DevTools MCP 분석

에이전트가 실제 Chrome을 조작·계측하게 해 주는 Google 공식 MCP 서버입니다. 핵심은 “브라우저 자동화”보다 DevTools급 진단(성능 트레이스·네트워크·콘솔·힙)을 토큰 아끼는 요약으로 돌려준다는 점입니다.

63개 도구, 어디에 몰려 있나

카테고리별 도구 수. 회색은 기본값이 꺼짐이라 플래그를 줘야 보입니다.

기본 켜짐플래그 필요

기본 상태로 보이는 도구는 33개. Memory 14개는 --memoryDebugging 이 있어야 노출됩니다.

전문가 평가: 엔지니어가 알아야 할 설계 판단

이 서버의 차별점은 “스크린샷 보고 클릭하는 봇”이 아니라 접근성 트리 스냅샷(uid) + DevTools 분석 엔진입니다. Playwright MCP와 겹치는 부분은 입력·탐색 16개뿐이고, 나머지 47개는 진단 도구입니다. 자동화만 필요하면 --slim, 디버깅이면 풀 모드가 맞습니다.

공식 설계 원칙 7개 (docs/design-principles.md)

  • 토큰 최적화 — “LCP 3.2s”가 JSON 5만 줄보다 낫다
  • 작고 결정적인 블록 — 만능 버튼 대신 click·screenshot 조합
  • 값 대신 참조 — 트레이스·영상·스크린샷은 파일 경로로
  • 자기 치유형 오류 — 오류에 원인과 해결책을 담아 반환
  • 에이전트 비종속 · 사람/기계 동시 가독 · 점진적 복잡도

보안·프라이버시 체크포인트

  • 브라우저 내용 전체가 MCP 클라이언트에 노출 — 로그인된 개인 프로필로 쓰지 말 것
  • 사용 통계 수집 기본 켜짐 → --no-usage-statistics
  • CrUX 조회로 URL 외부 전송 → --no-performance-crux
  • 격리: --isolated(임시 프로필), --allowedUrlPattern, --redactNetworkHeaders, --javascriptEvaluation=false

초보자 실수 vs 숙련자 방식

상황초보자가 흔히 하는 것숙련자가 하는 것

Claude Code에 붙이기

MCP만 (가장 단순, 본인 PC에서):

claude mcp add chrome-devtools --scope user -- npx chrome-devtools-mcp@latest --isolated --no-usage-statistics

MCP + 공식 스킬 8개 (플러그인):

/plugin marketplace add ChromeDevTools/chrome-devtools-mcp
/plugin install chrome-devtools-mcp@chrome-devtools-plugins

설치 뒤 Claude Code를 새로 시작해야 도구가 보입니다. 첫 확인 프롬프트: “Check the performance of https://developers.chrome.com”.

고급 사고법: 질문을 도구 체인으로

  1. 가설부터 — “느리다”가 아니라 “LCP 요소가 늦게 발견되는가, 늦게 그려지는가”
  2. 계측 — performance_start_trace(reload) → performance_stop_trace → 인사이트 이름으로 performance_analyze_insight
  3. 원인 좁히기 — list_network_requests로 리소스 타이밍, get_css_styles로 렌더 차단 확인
  4. 재현 조건 고정 — emulate로 CPU 4x·Slow 4G, 같은 조건에서 전후 비교
  5. 코드 수정 없이 관찰 — set_logpoints로 소스맵 위치에 로그, mock_network로 API 응답 바꿔 가설 검증
