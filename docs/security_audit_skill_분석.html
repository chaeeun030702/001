Cloudflare security-audit: 찾는 에이전트와 반박하는 에이전트를 분리한 6단계 감사

후보를 많이 모은 다음, 다른 에이전트가 반박을 시도해 살아남은 것만 확정하는 구조입니다. 기존 스킬 중 가장 가까운 것은 기본 제공 /security-review(변경분 리뷰)이고, 저장소 전체 감사·검증기·커버리지 원장까지 갖춘 스킬은 아직 없었습니다.

1. 이미 가진 스킬과 비교: 겹치는 부분은 일부, 전체 감사는 새로 생긴다

스킬범위검증 방식산출물판정

2. 파일 구성: 핵심 절차 4개 + 도메인 동반 문서 11개

빨강은 모든 감사에 쓰는 핵심 절차, 파랑은 대상 종류에 따라 골라 쓰는 공격 분류입니다(줄 수).

검증기 JS 2개(1,645줄)와 테스트 2개(1,392줄)는 별도입니다. 이 세션에서 테스트 65개를 돌려 모두 통과했습니다.

3. 판정은 셋, 심각도는 확정에만

심각도 기준

4. 상위 1% 관점: 초보자는 "찾기"에, 숙련자는 "반박"과 "커버리지"에 시간을 쓴다

초보자가 흔히 하는 실수

  • 체크리스트 위반(헤더 누락, 버전 낡음)을 취약점으로 보고한다.
  • 찾은 사람이 스스로 확인해 확증 편향이 그대로 남는다.
  • 한 번 돌리고 "다 봤다"고 한다. Cloudflare 측정으로 1회 실행은 반복 실행 총합의 약 절반만 찾았다.
  • 배포·프록시 설정을 추측해서 있다/없다를 단정한다.

숙련자가 다르게 하는 점

  • 후보마다 신뢰 경계를 명시한다: 누가, 무엇을 넣어, 어떤 통제를 넘어, 누구에게 어떤 결과.
  • 발견자와 검증자를 분리하고, 검증자에게는 반박을 시킨다.
  • 커버리지 원장으로 "본 곳 / 못 본 곳 / 범위 밖"을 숫자로 남긴다.
  • 모르는 사실은 needs_validation으로 두고 정확히 무엇이 막혔는지 적는다.

고급 수준의 사고

  • 심각도는 "통제를 완전히 무력화했나, 약화만 했나"로 가른다. 피해를 한 문장으로 못 쓰면 한 단계 낮다.
  • 다층 방어에서 A층이 막으면 B층 부재는 강화 권고일 뿐이다.
  • 수정은 마지막 신뢰 결정 지점에서 가장 좁게, 회귀 테스트와 함께 제안한다.
  • 예산이 모자라면 품질을 줄이지 않고 범위를 줄인다(quick / scoped).

5. 저장소에 추가한 내용과 쓰는 법

skills/security-audit/에 원본 20개 파일을 그대로 넣고 LICENSE(MIT)와 출처·사용법을 적은 SOURCE.md를 더했습니다. 기존 스킬처럼 업로드용 skills/security-audit.zip도 만들었습니다.

질문이나 부분 리뷰는 가이드 모드로 필요한 부분만 쓰고, "이 코드베이스 보안 감사해줘"처럼 명시적으로 요청할 때만 6단계 전체를 돌며 결과를 저장소 밖 ~/security-audit-skill/<repo>/run-N에 씁니다.

대상 코드를 실행하려면 네트워크 차단·환경 변수 허용목록·쓰기 제한·자원 한도를 갖춘 OS 샌드박스가 필요합니다. 없으면 실행하지 않고 needs_validation으로 남깁니다. 이 클라우드 세션은 그 조건을 다 갖추지 못하므로, 여기서는 소스 정적 분석 위주로 돌게 됩니다.

전체 감사는 서브에이전트를 많이 띄우는 작업이라 비용이 큽니다. 처음에는 quick 프로필이나 예산(에이전트 호출 수)을 지정해 쓰는 것을 권합니다.
