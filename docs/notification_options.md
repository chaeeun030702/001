# 내 웹에서 나에게 문자·이메일 보내기 — 대안 정리

대상: 안전관리자 채용 브리핑 (`briefings/latest.html` 아티팩트 + 매일 수집 GitHub Actions + 20:00 KST Routine)

## 먼저 알아둘 제약

- 브리핑 웹 페이지는 **브라우저에서만 도는 정적 HTML**이다. 서버가 없어서 페이지가 닫혀 있으면 아무것도 못 보낸다.
- 페이지 안에 메일·문자 API 키를 넣으면 **열람자 누구에게나 키가 노출**된다. 키는 반드시 서버 쪽(GitHub Secrets, Routine, 커넥터)에 둔다.
- 그래서 "누가 페이지를 열 때" 보내는 방식(A)과 "자동으로 보내는 방식"(B~E)을 나눠서 본다.

## 한눈에 비교

| # | 방식 | 이메일 | 문자(SMS) | 자동 발송 | 비용 | 난이도 | 비고 |
|---|---|:-:|:-:|:-:|---|:-:|---|
| A | 웹 버튼 → Gmail 커넥터(`mcp` 기능) | O | X | 버튼 클릭 시 | 무료 | 낮음 | 내 Gmail 계정으로 발송, 열람자 동의 필요 |

## 방식별 설명

### A. 웹 버튼 → Gmail 커넥터
- 페이지에 `capabilities: {mcp: {servers: [{server: "Gmail", tools: ["send_message"]}]}}`를 선언하고, 버튼 클릭 시 `callTool`로 **나에게** 메일 발송.
- 장점: 별도 서버·키 불필요. 단점: 열람자 본인의 Gmail 권한으로 나가므로 **다른 사람이 열면 그 사람 계정이 쓰이거나 실패**한다. 이 권한을 선언하면 공개 링크 공유가 막힌다. 보낼 주소는 코드에 고정(자기 자신).
- 용도: "이 필터 결과를 메일로 받기", "선택한 공고 목록 메일로 보내기" 같은 수동 기능.

### B. GitHub Actions 알림 단계 (권장 1순위)
- `safety-jobs-briefing.yml`의 `Commit briefing` 뒤에 단계를 추가한다. `briefings/latest.json`에서 **신규 공고**만 뽑아 본문을 만든다.
- 이메일: Gmail SMTP(앱 비밀번호) 또는 Resend·SendGrid 같은 메일 API. 값은 저장소 **Settings → Secrets**에 `MAIL_USER`, `MAIL_APP_PASSWORD`, `MAIL_TO`로 보관.
- 신규 공고가 0건이면 발송을 건너뛰어 소음을 줄인다.
- 주의: 이 저장소가 공개라면 로그에 주소·키가 찍히지 않게 한다.

### C. 20:00 Routine이 Gmail로 발송
- 이미 20:00 Routine이 `briefings/latest.*`를 읽어 브리핑을 전달한다. 같은 Routine에 "요약을 Gmail로 나에게 보내기" 단계를 더하면 된다.
- Routine 생성·수정 시 `connectors: ["Gmail"]`을 허용해야 한다. 완료 알림은 Routine 자체 옵션(`notifications: {push, email}`)으로도 받을 수 있다(새 세션을 여는 Routine에 한함).
- 장점: 코드·키가 필요 없다. 단점: 20:00에 Routine이 실제 도는 시점에만 발송.

### D. 메신저 푸시 — 문자의 가장 쉬운 대체
| 도구 | 설정 | 비고 |
|---|---|---|
| 카카오톡 "나에게 보내기" | 카카오 개발자 앱 등록 → OAuth 토큰(리프레시 토큰 갱신 필요) → 메모 API | 한국에서 체감상 문자와 가장 비슷, 무료 |
| 텔레그램 봇 | BotFather로 봇 생성 → `BOT_TOKEN`, `CHAT_ID` Secrets → `curl`로 발송 | 가장 간단, 무료, 4096자 |
| ntfy.sh | 무작위 토픽 이름만 정하면 끝(가입 불필요) | 토픽 이름이 곧 비밀번호이므로 추측 어렵게 |
- B의 GitHub Actions 단계에서 `curl` 한 줄로 보낼 수 있다.

### E. 진짜 문자(SMS/LMS)
- 업체 후보: Solapi(구 쿨SMS), NHN Cloud Notification, 네이버 클라우드 SENS, Aligo, 해외는 Twilio.
- 국내는 **발신번호 사전 등록(본인 인증)**이 법적으로 필요하다. 내 번호로 나에게 보내는 경우도 등록해야 한다. 건당 과금(SMS는 수 원~십수 원, 장문 LMS는 더 비쌈 — 가입 시 현재 단가 확인).
- API 키는 반드시 GitHub Secrets나 Routine 쪽에 둔다.
- "꼭 문자여야 하는 이유"(휴대폰 알림이 켜져 있지 않다 등)가 없다면 D로 충분하다.

### F. `mailto:` / `sms:` 링크
- `<a href="mailto:내주소?subject=…&body=…">`, `<a href="sms:내번호?body=…">`.
- 서버·키·비용이 없고 구현이 5분이지만 **내 앱이 열려 "보내기"를 눌러야** 한다. 아티팩트 프레임 안에서는 링크 이동이 막힐 수 있어 새 탭(`target="_blank"`)으로 확인 필요.

## 추천 조합

1. **매일 자동 알림이 목적이면**: B(이메일) + D(텔레그램 또는 카카오 나에게 보내기, 문자 대용). 페이지를 열지 않아도 오고, 코드는 워크플로 한 단계로 끝난다.
2. **이미 Routine을 쓰고 있어 코드를 늘리기 싫으면**: C.
3. **웹에서 버튼으로 "지금 보내기"를 원하면**: A (또는 가장 단순하게 F).
4. **반드시 SMS여야 하면**: E. 발신번호 등록과 단가부터 확인.

## 결정이 필요한 것

- 알림 대상: 매일 신규 공고 요약인가, 웹에서 고른 공고를 즉석으로 보내는 것인가?
- 문자가 꼭 필요한가, 휴대폰 푸시(D)로도 충분한가?
- 받을 이메일·휴대폰 번호는 **저장소에 적지 말고** Secrets/Routine 설정에 둘 것.
