# 엔터프라이즈 AI UI 표준

모든 UI·문서형 결과물을 생성·수정할 때 이 규격을 최우선으로 적용한다. 모델의 기본 디자인 취향보다 이 문서의 규칙이 항상 우선한다.

## 해석 규칙(신뢰도 태그)

- `[Must]` 필수. 명시적 지시 없이 변경 금지
- `[Strong]` 기본값. 제품 요구가 없으면 그대로 사용
- `[Normalize]` 원본(디자인 파일·레거시) 오타 명칭은 import/codegen 계층에만 유지하고 공개 명칭은 정규화
- `[Fallback]` 미정의 시 접근성 기반의 관례적 패턴 적용
- `[Check]` 영구 표준화 전 시각·제품 검토 필요

## 핵심 원칙

`[Must]` 차분하고 신뢰감 있는 라이트 우선 엔터프라이즈 톤. 캠페인·에디토리얼 스타일 금지.
`[Must]` 강조는 위계·여백·보더·시맨틱 컬러·레이아웃 리듬으로. 장식적 효과(대형 그라데이션, 블롭, 임의 일러스트) 금지.
`[Must]` 주 인터랙션 컬러 `#0F6FFF`(dark `#3F8CFF`), 본문 텍스트 `#1D1F24` 계열, 기본 표면은 화이트/쿨뉴트럴, Pretendard, 최소 그림자.
`[Must]` **설명은 글이 아니라 구조로 한다.** 긴 문단 대신 요약 + 도식·차트·표·카드로 전달한다(아래 「정보 밀도와 시각화」 참조).

## 정보 밀도와 시각화

보고서·분석 문서·대시보드 등 읽을거리가 있는 모든 산출물에 적용한다.

### 텍스트 압축 규칙

`[Must]` 한 문단은 **최대 3문장**, 한 문장은 **60자 내외**. 그 이상이면 불릿·표·도식으로 분해한다.
`[Must]` 각 섹션 맨 앞에 **한 줄 결론(핵심 문장)**을 두고, 근거는 그 아래 시각 요소로 붙인다. 결론을 문단 끝에 숨기지 않는다.
`[Must]` 원문을 그대로 옮기지 않는다. 조문·규정·인용은 요약하고, 전문은 접힘(`<details>`) 또는 부록으로 내린다.
`[Must]` 같은 내용을 서술문과 표로 중복 설명하지 않는다. 둘 중 정보 밀도가 높은 하나만 남긴다.
`[Strong]` 문서 전체 본문 텍스트 비중 목표: **화면 면적의 50% 이하**. 나머지는 도식·차트·표·여백.
`[Strong]` 페이지 상단에는 항상 **요약 블록**(3~5개 핵심 카드 또는 KPI)을 둔다.
`[Strong]` 목록은 7±2개를 넘기지 않는다. 넘으면 그룹핑하거나 표로 전환한다.

### 시각화 선택 기준

| 전달하려는 것 | 쓰는 것 | 쓰지 말 것 |
| --- | --- | --- |
| 핵심 수치·현황 | KPI 카드(수치 700 + 라벨 + 증감) | 문장 속 숫자 나열 |
| 항목 간 비교 | 가로/세로 막대 | 파이(3개 초과 시) |
| 시간 변화·추세 | 라인·영역 차트 | 표 나열 |
| 구성비 | 100% 스택바, 도넛(항목 ≤3) | 3D·다중 파이 |
| 위계·분류 체계 | 트리·계층 다이어그램 | 들여쓰기 문단 |
| 절차·흐름 | 스텝 플로우, 타임라인 | 번호 문단 |
| 관계·영향 | 매트릭스, 관계도 | 서술 설명 |
| 조건 분기 | 의사결정 트리 | 중첩 불릿 |
| 다차원 비교 | 비교 표(행=항목, 열=기준) | 항목별 문단 |

`[Must]` 모든 그래픽은 **inline SVG 또는 CSS**로 직접 생성한다. 외부 차트 라이브러리·CDN·이미지 링크·스크린샷 금지(오프라인에서 깨지면 안 된다).
`[Must]` 차트 색은 시맨틱/액센트 토큰만 사용. 기본 계열은 primary → accent-skyblue → accent-purple → accent-orange → accent-pink 순.
`[Must]` 모든 차트에 제목, 축·단위 라벨, 값 라벨 또는 범례를 붙인다. 색 하나만으로 구분하지 않는다(패턴·라벨 병기).
`[Must]` 데이터가 없거나 추정치면 도식 안에 `추정`·`데이터 없음`을 명시한다. 수치를 만들어내지 않는다.
`[Strong]` 차트는 카드(`--color-bg-surface` + 보더 + `--radius-md`) 안에 담고, 차트 아래에 **한 줄 해석**을 캡션으로 붙인다.
`[Strong]` 구현 골격은 `references/visualization.md`의 패턴을 그대로 가져다 쓴다.

### 문서 리디자인 절차

원문(긴 텍스트 보고서)을 표준에 맞게 고칠 때 순서:

1. 원문에서 **사실·수치·관계**만 추출한다(수사·반복 제거).
2. 항목별로 위 「시각화 선택 기준」 표에 따라 표현 형식을 정한다.
3. 상단 요약(카드/KPI) → 본문 섹션(한 줄 결론 + 그래픽 + 짧은 해석) → 부록(원문·출처) 순으로 재배치한다.
4. 남은 문장을 다시 줄인다. 그래픽이 말해주는 내용은 문장에서 삭제한다.
5. 출처·근거 조문은 표 또는 각주로 정리하고 본문 흐름에서 뺀다.

## 타이포그래피

`[Must]` 폰트: `"Pretendard Variable", "Pretendard", "Apple SD Gothic Neo", "Noto Sans KR", "Segoe UI", Roboto, -apple-system, BlinkMacSystemFont, sans-serif`. 데이터·코드·ID는 `"SF Mono", SFMono-Regular, Menlo, Consolas, monospace`.
`[Must]` 가중치는 400/600/700만 사용(400 본문, 600 라벨·강조, 700 제목·핵심 수치). 승인 스케일 외 커스텀 사이즈 생성 금지.

스케일은 기존 표준 대비 **2단계 상향**한 값이다(가독성 우선). 아래 값만 사용한다.
크기를 키운 만큼 **줄간격(line-height)은 계열마다 반드시 지정**한다. 큰 글자일수록 좁힌다.

| Token | Size | Weight | Line-height | 토큰 |
| --- | --- | --- | --- | --- |
| Display1~4 | 80 / 72 / 56 / 44px | 700 | 1.1 | `--lh-display` |
| Title1~3 | 40 / 36 / 32px | 700 | 1.2 | `--lh-title` |
| Heading1~3 | 28 / 24 / 22px | 700 | 1.3 | `--lh-heading` |
| Body1~3 | 20 / 18 / 16px | 400 | 1.7 | `--lh-body` |
| Label1~2 | 15 / 14px | 600 | 1.4 | `--lh-dense` |
| Caption1~3 | 14 / 13 / 12px | 400 | 1.5 | `--lh-caption` |

`[Must]` 본문 기본값은 **18px**(Body2), 최소 텍스트는 12px 이상. 14px 미만 본문 사용 금지.
`[Must]` 표·차트 라벨·캡션도 14px 이상으로 한다(SVG 내부 텍스트 포함).
`[Must]` **line-height 1.7은 본문 전용이다.** 제목·수치·라벨이 본문 줄간격을 상속하면 줄간격이 벌어지고 배치가 무너진다. Title/Display는 1.1~1.2, Heading은 1.3, 라벨·표 셀은 1.4로 계열별 `--lh-*` 토큰을 지정한다.
`[Must]` 버튼·인풋·테이블 행·사이드내비 행은 **고정 `height` 대신 `min-height`**(`--control-h` 44px, `--row-h` 56px, `--nav-row-h` 52px)를 쓴다. 큰 글자·줄바꿈이 잘리지 않게 한다.

`[Must]` 표·금액·지표 등 정렬 숫자는 tabular numerals. 같은 데이터 맥락에서 tabular/proportional 혼용 금지.
`[Strong]` 본문 줄길이는 70~80자(약 840px) 이하로 제한한다. 전폭 문단 금지.
`[Strong]` 여백·간격은 `--space-*`(4px 베이스) 토큰으로 준다. 폰트를 키운 만큼 제목 위 간격(≈32px)·섹션 간격(≈48px)도 함께 키운다.
`[Strong]` 요약 수치·행 높이: 테이블 행 min 56px, 버튼·인풋 min 44px, 사이드내비 depth1 min 52px·depth2 min 44px. 값은 `references/design-tokens.css`의 토큰을 그대로 쓴다.

- `secondary` `#1D1F24` / `#E9EBEF`

- 배경: default `#FFFFFF`/`#1D1F24`, content-canvas `#EEF1F5`/`#15171C`, alternative `#F2F3F6`/`#282B33`, elevated `#F2F3F6`/`#333741`
- 보더: strong `#CCD0D6`/`#4A505F`, default `#E2E4E9`/`#333741`, divider `#E9EBEF`/`#282B33`
- 상태: success `#15B874`/`#44C690`, warning `#FFA833`/`#FFB95C`, error `#E63B3B`/`#EB5E5E`
- 액센트: orange `#FE6F3F`, purple `#B357FF`, pink `#F553DA`, skyblue `#00BDDE`(다크: `#FE8C65`, `#C279FF`, `#F775E1`, `#33CAE5`)
- 딤: `#1D1F24 50%`

`[Must]` 블루가 유일한 주 인터랙션 색. 웜 액센트를 주요 액션 색으로 사용 금지. 시맨틱 컬러는 상태 전달용(차트 계열색은 예외적으로 액센트 사용 가능).
`[Must]` 다크 모드는 단순 반전이 아닌 전용 다크 토큰 사용.

## 레이아웃·셸

`[Must]` 대시보드·운영 제품은 데스크톱 우선(스티키 헤더 + 고정 사이드내비 + 독립 스크롤 콘텐츠).
`[Must]` 라이트: 헤더/내비 `#FFFFFF`, 콘텐츠 캔버스 `#EEF1F5`. 다크: 헤더/내비 `#1D1F24`, 콘텐츠 `#15171C`.
`[Must]` 모바일 기준 375px, 좌우 패딩 20px, 터치 타깃 40~56px. XS에서 사이드내비는 드로어/시트로 전환.
`[Strong]` 보고서형 문서도 셸 구조를 따른다: 상단 헤더 + 좌측 목차 내비 + 우측 본문(카드 그리드). 목차는 현재 섹션을 `aria-current`로 표시한다.

### 사이드 내비게이션

`[Must]` 데스크톱 기본형은 고정·상시 노출·라벨 표시 확장형. 별도 요청 없이 접힘/아이콘 전용 토글 추가 금지.
`[Must]` 앱 셸의 일부로 좌측에 붙은 연속 표면(우측 보더). 떠 있는 카드·라운드 패널 금지. 평면 링크 나열 금지, 섹션형 IA 트리로 구성.
`[Strong]` `SideNav → SideNavSection → SideNavItem`. 확장 폭 약 300px, 컴팩트 약 80px. depth1 행 min 52px(`--nav-row-h`), depth2 min 44px(`--nav-row-h-sub`), 컴팩트 레일 56×56px. 행은 고정 height가 아니라 min-height로 둔다. 상태: default/hover/focus/selected/disabled.

### 헤더

`[Must]` 브랜드 락업: 로고 좌측 + 얇은 수직 구분선 + 서비스명 우측, 서비스명은 한 줄 고정(no-wrap).
`[Must]` 검색은 입력 컨트롤만 렌더. 옆에 "Search"·"통합 검색" 같은 라벨 표시 금지(placeholder + 접근성 라벨 사용).
`[Must]` 유틸리티(테마·알림·도움말)는 아이콘 전용 버튼, 24×24 캔버스, 1.5px 스트로크, 외곽선 박스 없이 조용한 호버 배경.
`[Must]` 프로필 트리거는 아바타 + 사용자명 한 줄만. 부서·직책·이메일 등은 드롭다운 내부에만 노출.

## 컴포넌트

`[Must]` 새로 만들기 전에 기존 디자인 시스템 컴포넌트 재사용 여부를 먼저 확인한다.

- 버튼: primary `#0F6FFF`(다크 `#3F8CFF`) + 화이트 텍스트, 라디우스 8~12px, primary/secondary/dark/danger, loading은 상태로 처리, 아이콘 전용 버튼은 접근성 라벨 필수
- 카드: 화이트 표면, 그림자보다 보더·여백 우선, 라디우스 8(compact)/12(standard)/16(featured)
- KPI 카드: 라벨(15px/600, muted) + 수치(40~56px/700, tabular) + 증감(시맨틱 컬러 + 부호 + 텍스트). 수치만 크게 두고 장식 금지
- 인풋: 명확한 포커스, placeholder는 라벨 대체 불가, 라벨·헬퍼·에러 프로그램적 연결
- 선택 컨트롤: 다중=Checkbox, 소수 배타=Radio, 항목 많으면 Select, 즉시 반영 on/off만 Switch
- 테이블: 정렬 숫자 tabular, 운영 행 높이 52px 이상, 대량 데이터는 페이지네이션·필터·검색
- 오버레이: Dialog는 스크림 있는 진짜 모달(title/contents/function/button 슬롯), 바텀시트는 상단 모서리만 라운드
- 아바타: 원형, size lg40/md32/sm24, type Initial·Avatar·Check, status Online→success·Busy→error·Offline→neutral, 헤더는 24px 기본. 커스텀 일러스트 아바타 금지
- 피드백: 지속 메시지는 Alert, 일시 피드백은 Toast(치명적 오류를 Toast만으로 처리 금지), 숫자 알림은 count badge, 아이콘 전용 컨트롤은 Tooltip 보조
- 로딩: 레이아웃이 정해진 곳은 Skeleton, 로컬 액션은 inline Spinner, 초기·전체 전환만 중앙 로딩, 처리 중 컨트롤 비활성화

## 접근성

`[Must]` 키보드 활성화, 명확한 focus-visible, 색상 단독 의존 금지.
`[Must]` 모달은 focus trap·포커스 복귀, Escape 닫기.
`[Must]` 유효성 오류는 색상 + 텍스트 동시 전달. 비활성 컴포넌트는 상호작용 불가 + 시각적 구분.
`[Must]` 아이콘 상태는 시맨틱 컬러·투명도·부모 표면으로 표현하고 아이콘 형태를 다시 그리지 않는다.
`[Must]` 차트·도식은 `role="img"` + `aria-label`(또는 인접 표)로 동일 정보를 텍스트로도 제공한다. 순수 장식 SVG는 `aria-hidden="true"`.

## 아이콘

`[Must]` 기본 24px(컴팩트 20/16px), 비율 왜곡 금지, 스트로크 1.5~2px 단일 패밀리, 제품 내 라이브러리 혼용 금지.
`[Must]` 제품 UI는 inline SVG 사용. 이모지·3D·마스코트·장식 아이콘 금지.
`[Must]` SVG 색은 `currentColor` 또는 시맨틱 토큰으로 제어한다.
`[Strong]` 사내 승인 아이콘 세트가 제공되면 그 세트만 사용하고, 한 제품 안에서는 하나의 변형(line/solid 등)을 일관되게 쓴다.

## 라디우스·그림자

`[Must]` 라디우스 8~16px(배지 4px, 인풋·컴팩트 8px, 카드 12px, 시트 16px, pill 9999px).
`[Strong]` 그림자 level1 `0 1px 3px rgba(0,0,0,0.06)`, level2 `0 2px 8px rgba(0,0,0,0.08)`, level3 `0 4px 12px rgba(0,0,0,0.12)`. 컬러·과장 그림자 금지. 그림자를 1차 위계 수단으로 사용 금지.

## 브랜드 자산 취급

`[Must]` 로고·심볼은 공식 자산 파일이 제공된 경우에만 사용한다. 텍스트·CSS·AI 생성 그래픽으로 로고를 재현하지 않는다.
`[Must]` 로고 비율 유지, 변형·리컬러·회전·크롭 금지.
`[Must]` 필요한 공식 자산이 없으면 임의 생성·대체하지 말고, 해당 자리를 비운 뒤 자산 부재를 보고한다.
`[Must]` 샘플·예시 데이터에 실명·부서명·이메일 등 개인·조직 식별 정보를 넣지 않는다(가명·일반 명사 사용).

## 산출물 체크리스트

전달 전 확인한다.

- [ ] Pretendard 폰트 스택과 승인된(2단계 상향) 타이포 토큰만 사용했는가
- [ ] 본문이 18px 기준이고 12px 미만 텍스트가 없는가
- [ ] 제목·수치가 본문 1.7을 상속하지 않고 계열별 line-height(`--lh-*`)를 쓰는가
- [ ] 버튼·인풋·행이 고정 height가 아니라 min-height라 큰 글자가 잘리지 않는가
- [ ] 색상이 시맨틱 토큰(CSS 변수) 기반이며 임의 hex 하드코딩이 없는가
- [ ] 주 액션이 블루이고 웜 액센트를 액션 색으로 쓰지 않았는가
- [ ] 셸 분리(헤더/내비 vs 콘텐츠 캔버스)가 적용되었는가
- [ ] 사이드내비가 고정·확장형이며 카드처럼 떠 있지 않은가
- [ ] 헤더 검색이 입력만, 프로필이 아바타+이름 한 줄인가
- [ ] 상단에 요약 카드/KPI가 있고, 각 섹션이 한 줄 결론으로 시작하는가
- [ ] 3문장 초과 문단, 원문 복붙, 중복 설명이 없는가
- [ ] 비교·추세·구성비·절차가 문장이 아니라 차트·도식으로 표현되었는가
- [ ] 차트에 제목·단위·값 라벨·해석 캡션과 접근성 라벨이 있는가
- [ ] 모든 그래픽이 inline SVG/CSS이며 외부 라이브러리·이미지 의존이 없는가
- [ ] 포커스 표시·키보드 조작·라벨 연결이 되어 있는가
- [ ] 그림자·라디우스가 승인 범위 내인가
- [ ] 승인된 브랜드·아이콘 자산을 사용했거나 부재를 보고했는가
- [ ] 실명·부서·이메일 등 개인정보가 노출되지 않았는가
