## 파일
- `latest.html` : 최신 브리핑(편집, A4 인쇄, '편집본 저장' 버튼 포함 HTML 한 파일)
- `archive/env_brief_YYYY-MM-DD.html` : 날짜별 사본

## 브리핑 구성 (원본 분석)
1. 머리말: 날짜 칩 `YYYY년 M월 D일 (요일)`, 제목, 조사 대상 부제
2. 핵심 요약 5~6줄: 턴키 유찰/수의계약 흐름, 지자체 민자(BTO-a 소각), 재정 소각장, 대형 하수 민자, LH/K-water 발주, 4개 업체 동향
3. 지자체 표 (지자체 · 사업명/추진 내용 · 방식 · 사업비 · 단계 · 출처)
   - 서울, 인천, 용인, 파주, 김포, 가평, 오산, 속초, 구미, 경주, 포항, 대구, 전주, 고창, 광주, 진주 등 + 신규 발견 지자체
   - 단계 배지: `st-blue`(진행), `st-green`(확정/계약/공사), `st-amber`(지연/재공고/미정), `st-red`(유찰/반발/지적), `st-gray`(예정/확정 재정)
4. 주요 기관 표: 한국환경공단, K-water, LH, 수도권매립지관리공사, 기타 발주기관(새만금개발공사 등)
5. 업체 카드 4개: 금호건설, 태영건설, 코오롱글로벌, 계룡건설 (+ 공통 흐름 callout)
6. 향후 주요 일정 표 (지난 일정은 빼고 결과를 본문에 반영)
7. 참고 출처 / 작성 기준 문구

## 매주 절차
1. 직전 브리핑(`latest.html`)을 읽고 항목별로 "지난주 이후 변화"를 찾는다 (최근 7~10일 보도, 공고 위주).
   - 지난 일정(현장설명, PQ, 개찰, 민투심 등)의 결과를 반드시 확인해 단계 배지를 갱신한다.
   - 새로 나온 환경 민자(BTO-a, BTL, 제3자 제안공고 - KDI PIMAC), 턴키 발주/유찰/적격자 선정은 행으로 추가한다.
   - 변화 없는 항목은 그대로 두되, 오래되어 의미가 없어진 항목은 정리한다.
2. 조사는 서브에이전트 3개로 병렬 진행: ① 지자체 ② 주요 기관 ③ 4개 업체. 에이전트 작업현황 아티팩트를 갱신한다(CLAUDE.md 규칙).
3. 모든 행에 실제로 열어 본 원문 링크를 단다. 확인 못한 내용은 싣지 않는다. 사업비는 보도 추정치로 표기.
4. 문체: 원본처럼 쉼표 나열, '~습니다' 체, 가운데점(·) 대신 쉼표. 인쇄 CSS와 저장 스크립트는 건드리지 않는다
   (저장 파일명 `환경_민자턴키_동향브리핑_YYYY.MM.DD.html`, `<title>`, 날짜 칩, 하단 작성일만 날짜에 맞게 바꾼다).
5. `latest.html` + `archive/` 사본 저장 → 커밋, 푸시 → 아티팩트 같은 URL로 게시 후 open → docs 사본을 render로 전달.
